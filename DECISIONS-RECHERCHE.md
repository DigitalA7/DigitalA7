# Décisions de recherche

## Décision 1 : partir du code

Les affirmations techniques sont d’abord rattachées aux fichiers et aux fonctions observables. Les résumés de README servent d’orientation, pas de preuve suffisante.

## Décision 2 : séparer les garanties

Confidentialité, intégrité, disponibilité, finalité et attribution sont analysées séparément. Une propriété démontrée dans un circuit ne s’étend pas automatiquement à l’interface ou à la gouvernance.

## Décision 3 : exposer les limites

Chaque parcours indique ce qui est lu, ce qui est interprété et ce qui n’a pas été testé. Cette séparation évite de transformer une analyse documentaire en promesse de production.

## Décision 4 : comparer par critères

Les comparaisons utilisent sécurité, coûts, hypothèses, ergonomie, évolutivité et vérification. Aucun indicateur unique ne décide à lui seul d’une architecture.
